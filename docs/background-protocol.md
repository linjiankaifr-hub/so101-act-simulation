# 桌面背景泛化协议

## 范围

在既有SO101视觉抓放任务上做一次受控桌色增强实验，产出可重跑代码、实际训练、最终评测和Obsidian初学者讲解。不进行新硬件购买、云算力租赁、真实机器人部署或最终测试驱动的自动调参。

源起：先在新的开发种子22000—22019、固定桌色(0.25,0.35,0.40)上评估旧亮度实验两模型，诊断背景弱点。这40次诊断不参与训练或模型选择，不与新的100次最终成绩直接比较改善幅度。

## 数据与掩码

原始H5与回合划分保持原样。重放每条训练专家轨迹，逐帧与既有H5核对状态、动作、物体位置（最大绝对误差容许1e-6）和阶段，并核对回合长度与成功结果。通过后用MuJoCo几何分割生成两相机桌面mask。

掩码仅选 work_table 所属geom，机械臂、方块、目标标记具有其他geom ID。像素边缘存在抗锯齿近似；图片乘色与实际渲染不同，必须以MuJoCo真实新桌色测评验证。

data/background_masks/{base,random}.h5保存训练回合mask；对应JSON锁定原始H5、manifest、几何/专家/生成器源码、回合顺序、掩码指纹和实际最大重放误差。mask不导出为策略输入，不用于验证或自主推理。

## 分集

- 已有训练/验证/历史开发/历史测试全部保留。
- 新开发22000—22019：两新模型分别测试standard与固定background，80回合；不据此改变预定配方。
- 新最终60000—60099：两新模型分别测试standard与background_test，400回合；4种桌色通过seed%4选择，每种25回合。总计100个配对初始条件，不称为400个独立初始条件。
- 先诊断旧模型、固定配方、训练、冻结，再做最终测试；不把最终失败回合加入本轮训练。

## 保存和缓存

results/background/protocol.json在任何新训练启动前写入。记录数据/manifest/掩码/核心代码指纹、顺序回合划分、桌色、种子、训练预算和旧5模型指纹。每个run在启动前绑定协议指纹；已有训练若缺少绑定或绑定不同，拒绝复用。

训练快照按验证L1选择并复制到deploy；评测身份包含权重、归一化、配置、任务版本、种子、条件与动作窗口。正式评测缓存只在身份匹配时使用。脚本每个条件保留一段真实成功与失败录像，再为代表回合生成逐步渲染视频。

原第一轮与亮度实验源码分别以历史Git提交复现。当前核心扩展会触发旧亮度协议源码指纹检查，因此旧亮度实验使用cc7f803；不能为通过检查覆盖旧protocol。历史权重、数据、成绩继续保持，Windows审计独立核对。

## 验证

1. 整体pytest验证状态/动作/物理/对齐/桌面增强/旧功能。
2. 全量重放对齐审计，两个模型实际6000次更新和参数变化。
3. 初始化、架构、归一化、回合顺序一致。
4. 最终每个回合种子、分数、模型身份、成功条件与无专家输入。
5. 配对得失、分桌色成功率与失败类型。
6. 真实视频和训练图人工查看；Obsidian附件哈希一致。
7. Windows脚本独立验证数据、源码、掩码、历史模型及520次诊断/评测中的核心记录。
8. 一个独立只读代码审查；记录质疑和验证裁定。

## 命令

在项目目录的PowerShell：

```powershell
.\run_background.ps1 -Status
.\run_background.ps1
.\scripts\audit_background.ps1
```

Status只读。完整入口执行掩码检查和匹配缓存的实验流水线。初次执行包含约100条示范重放、两次训练及测试；中断训练按原种子从头重做，保留中断目录。

若输入文件已经变更，不要为了重跑覆盖协议或旧权重，应创建新的实验名称、协议和独立分集。
