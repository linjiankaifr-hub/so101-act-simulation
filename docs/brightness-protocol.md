# 亮度增强单变量实验协议

用户已批准“仅增加训练图片亮度变化，与原方式做公平对照”。本次在原有流程上增加可选增强参数、独立实验入口与报告，不修改原始示范、已有模型和第一轮成绩。

- 训练数据：base的80回合训练示范＋random的20回合，共100回合。验证仍用base的20个完整独立回合。
- 两个新版本：brightness_control不增强；brightness_aug仅对训练RGB乘随机亮度因子，范围预先固定为[0.4,1.4]，再截断至[0,1]。两路相机共享当前样本的因子。
- 增强在ImageNet归一化之前进行；不改变关节状态、动作、回合、时间或补齐掩码；原始图像文件保持不变。
- 增强使用独立的、按worker隔离的NumPy生成器，避免消耗模型初始化和数据抽样的全局随机数。
- 两组均使用官方ACT原配置、ImageNet视觉骨干、seed42、batch8、6000次更新；记录并比较初始参数SHA256，验证集和部署时不做亮度增强。
- 不在本轮搜索多种增强强度：固定一个范围，控制实验规模；开发结果仅用于诊断，不用于调整配置后继续使用同一最终测试宣称独立结论。
- 开发阶段：21000—21019共20个新种子，两组分别测试standard和lighting，共80回合。
- 冻结模型后：50000—50099共100个新种子，两组分别测试standard和lighting，共400回合。三种旧模型的30000系列成绩原样保留。
- standard与lighting复用同一组种子，以配对比较光照改变；lighting沿用物理仿真的变暗光照，不把图片乘因子直接当测试环境。
- 成功判定沿用verified-pinch-lift-release-v2，20Hz控制、30步重新观察；评测不调用专家。
- 部署快照统一按原始验证集动作L1选择，记录选中步数和三个文件指纹。比较表同时给出成功增益和原成功但新失败的次数。
- 结果如实报告，包括标准场景退步或光照没有改善；只有一个训练种子，不宣称普遍统计结论，也不承诺80/100。
- 仅使用已有本机环境和GPU，不购买硬件、不租用算力、不上传数据。

验证：先写增强/标签不变/独立随机数/种子隔离/配对统计测试，确认失败后实现，运行完整pytest；再进行真实训练和自主评测，检查数据和模型指纹、初始参数、输入限制与完整逐局结果。按requesting-code-review技能进行一次独立最终代码复查。
